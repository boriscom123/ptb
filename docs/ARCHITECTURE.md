# Архитектура проекта PTB

Telegram-бот с админкой в виде миниприложения Telegram, модерацией чатов и AI-агентом для разработки проекта.

## Инфраструктура

- VPS `150.241.105.178`, домен `150-241-105-178.sslip.io` (бесплатный wildcard DNS на IP сервера).
- HTTPS: Caddy + Let's Encrypt (автоматическое получение и продление сертификатов).
- Все сервисы запускаются в Docker (docker compose):

| Сервис      | Назначение                                                         |
|-------------|--------------------------------------------------------------------|
| `caddy`     | Входная точка, HTTPS, проксирование API в `app`, раздача собранного фронтенда |
| `app`       | Laravel (PHP-FPM): API миниприложения, вебхук Telegram             |
| `queue`     | Обработчик очередей Laravel (модерация, уведомления, задачи агента) |
| `scheduler` | Задачи по расписанию (снятие временных ограничений, очистка)       |
| `postgres`  | Основная БД                                                        |
| `redis`     | Очереди, кэш, антифлуд                                             |
| `node`      | Пересборка фронтенда при изменениях (`vite build --watch`) в `frontend/dist` |
| `agent`     | Claude Code в изолированном контейнере для правок кода             |

- Swap 4 ГБ (сервер: 1 CPU, 2 ГБ RAM).
- Разработка ведётся в ветке `dev`, приложение на сервере запущено из неё в dev-режиме.
- Dev-сервер Vite наружу не публикуется (его постоянно сканируют боты в поисках уязвимостей чтения файлов): Caddy раздаёт только собранные файлы.

## Стек

- Backend: PHP + Laravel (последние стабильные версии).
- Frontend: Vue 3 + Vite + Pinia + Telegram Mini Apps SDK.
- БД: PostgreSQL (LTS), Redis.
- Telegram: библиотека Nutgram, получение обновлений через вебхук `POST /api/telegram/webhook`, защищённый секретным заголовком `X-Telegram-Bot-Api-Secret-Token`. Регистрация вебхука, команд и описаний — `php artisan bot:setup`.
- Локализация: русский и английский; язык определяется по `language_code` пользователя Telegram. Все тексты — в файлах переводов.

## Структура репозитория

```
backend/    Laravel-приложение (API, бот, модерация, очереди)
frontend/   Vue-миниприложение (админка)
docker/     Dockerfile'ы и конфигурация сервисов
docs/       Документация
compose.yaml
```

## Авторизация

- Миниприложение передаёт `initData` от Telegram в `POST /api/auth/telegram`; backend проверяет подпись (HMAC на основе токена бота) и возраст (не старше 24 часов), затем выдаёт JWT (HS256, библиотека `firebase/php-jwt`, срок `JWT_TTL`, по умолчанию 60 минут).
- Refresh-токенов нет: когда JWT истёк, фронтенд просто повторно авторизуется по `initData` и повторяет запрос.
- Guard `api` (драйвер `jwt`) — `Auth::viaRequest` в `AppServiceProvider`; доступ к админ-API — middleware `admin`.
- Пароли и логины не используются — пользователь идентифицируется по Telegram ID.
- Роли: `admin`, `user`. Хранение ролей допускает добавление новых без переделки.
- Первый администратор задаётся переменной `ADMIN_TELEGRAM_ID` в `.env`.

## Админка (миниприложение)

- Доступна только роли `admin`.
- Открывается кнопкой «Открыть админку» после `/start` и кнопкой меню в личном чате с ботом (обе показываются только администраторам).
- Разделы: «Пользователи» и «Чаты» (настройки модерации и журнал).
- «Пользователи»: список с поиском (имя, @username, Telegram ID) и фильтром по роли, карточка пользователя, изменение роли.
- Ограничения: нельзя изменить собственную роль и роль главного администратора (`ADMIN_TELEGRAM_ID`).
- При смене роли пользователь получает сообщение от бота, кнопка админки в его чате появляется или убирается (задача в очереди).
- Frontend: Vue 3, vue-router, Pinia, vue-i18n; оформление на цветах темы Telegram (`--tg-theme-*`), без UI-библиотек.

API админки:

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/telegram` | `initData` → JWT |
| GET | `/api/me` | текущий пользователь |
| GET | `/api/admin/users?search=&role=&page=` | список пользователей (по 20) |
| GET | `/api/admin/users/{id}` | карточка пользователя |
| PATCH | `/api/admin/users/{id}` | изменение роли `{role}` |
| GET | `/api/admin/chats` | чаты бота |
| GET | `/api/admin/chats/{id}` | чат и все правила с настройками и описанием полей |
| PATCH | `/api/admin/chats/{id}` | включение модерации `{moderation_enabled}` |
| PUT | `/api/admin/chats/{id}/rules/{rule}` | правило `{enabled, settings}` |
| GET | `/api/admin/chats/{id}/events?page=` | журнал нарушений (по 30) |

## Модерация

- Бот модерирует группы, супергруппы и группы обсуждений каналов, где он администратор с правом удалять сообщения. В самом канале пишут только администраторы — для комментариев бота добавляют в группу обсуждений.
- Чаты учитываются автоматически (`my_chat_member`): тип, название, статус бота и его права. Переход группы в супергруппу (`migrate_to_chat_id`) сохраняет настройки.
- Модерация в чате по умолчанию выключена, включается в админке.
- Движок правил (`app/Moderation`): правило — наследник `Rules\Rule` с описанием полей настроек (`list`, `select`, `number`). По полям строятся значения по умолчанию, валидация API и форма в админке. Новое правило = новый класс + строка в `config/moderation.php` + переводы названия на фронтенде.
- Общие настройки каждого правила: действие (`delete` — удалить, `mute` — удалить и запретить писать на `mute_minutes`).
- Правила сейчас: «Ссылки» (`links`, белый список доменов с поддоменами) и «Стоп-слова» (`stop_words`, слова и фразы целиком, `*` в конце — по началу слова, регистр и ё/е не важны).
- Проверяются новые и отредактированные сообщения (текст и подписи к медиа), срабатывает первое нарушенное правило.
- Не проверяются: администраторы чата (список кэшируется на 10 минут и сбрасывается при изменении участников), анонимные администраторы, автопересылка постов из привязанного канала.
- Журнал (`moderation_events`): автор, правило, причина, действие (`failed`, если удалить не удалось), текст сообщения.
- Отправители сообщений в группах сохраняются в `users` (роль `user`), чтобы журнал ссылался на пользователей.

## AI-разработка через бота

- Ставить задачи агенту может только `admin` (в личном чате с ботом).
- Агент — Claude Code по подписке Claude (токен из `claude setup-token`), работает в контейнере `agent`.
- Процесс: задача → агент вносит правки → прогоняет тесты → коммит сразу в `dev` → бот присылает описание изменений и кнопку «Откатить».
- Откат реализован в контейнере `agent` и не зависит от кода Laravel, поэтому работает, даже если правка сломала приложение.
- Ограничения: агент не имеет доступа к production-секретам и БД, не пушит в `main`.
- Лимиты подписки общие с остальным использованием Claude.

## Тесты

- Frontend: Vitest (`npm test`), в том числе проверка, что все строки переводов компилируются (символы `@ { } |` в vue-i18n нужно экранировать, например `{'@'}`).

- PHPUnit, отдельная БД `ptb_test` (создаётся init-скриптом PostgreSQL). Переменные в `phpunit.xml` принудительно перекрывают окружение контейнера, тест `TestEnvironmentTest` это проверяет.

## Секреты

Секреты (токен бота, `ADMIN_TELEGRAM_ID`, токен Claude, ключи JWT) хранятся только в `.env` на сервере и не коммитятся. Шаблон — `.env.example`.

## План реализации

1. Сервер и каркас: swap, Docker, ветка `dev`, монорепо, docker compose, HTTPS на sslip.io.
2. Бот: Laravel + Nutgram, вебхук, `/start`, сохранение пользователей, переводы ru/en.
3. Авторизация и админка: проверка `initData`, JWT, Vue-миниприложение, раздел «Пользователи».
4. Модерация: учёт чатов, движок правил, журнал, базовые правила.
5. AI-агент: контейнер `agent`, очередь задач, коммиты в `dev`, откат.
